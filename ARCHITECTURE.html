2UI 是怎么渲染的

SwiftUI 是声明式：你描述"界面应该长成什么样"，系统负责把它变成像素，并在数据变化时自动重画。

声明式 vs 命令式

传统(命令式)：手动 "把这个 label 文字改成 42"。
SwiftUI(声明式)：你写 Text("\(score)")，只要 score 变了，文字自动更新，你不用手动去改。

自动重画的开关
  • @Published：AppStore 里的状态，一变就通知
  • @EnvironmentObject：各页面"订阅"同一个 AppStore
  • 状态变 → SwiftUI 对比新旧 → 只重画变化的部分(高效)
本 App 的渲染要点
TabView .verticalPage表冠上下翻页，watchOS 标准导航
→
圆环 RingView用 Circle().trim 画进度弧 + 渐变描边
→
12h 曲线 Swift ChartsLineMark/PointMark + 压力分区色带
→
水波球 WaveFill正弦曲线 Path 填充，裁剪成圆

这些都是纯代码画的矢量图形，没有用图片素材，所以在任何表盘尺寸都清晰。

4数据存在哪（自己的数据）

这个 App 的数据分三类去处，各管一段。

数据存在哪格式 / 机制谁能读
喝水量、药、餐、提醒次数、压力历史UserDefaults

group.com.lichaochen.mywatch		JSON，存在共享的 UserDefaults(suiteName:)主 App + Widget

系统级，不在 App 沙盒		系统统一管理，App 只是"申请读取"所有获授权的 App
沙盒概念：每个 App 有自己独立的私有文件夹(沙盒)，互相看不到。UserDefaults 就在沙盒里。App Group 是 Apple 开的一道"共享小门"，让主 App 和它的 Widget 扩展能读同一块地方——这就是卡片能拿到最新数字的原理。

5watchOS 三大机制详解

5.1 本地通知（提醒）

排程UNCalendarNotificationTrigger
→
交给系统时钟每天到点自动触发
→
系统弹横幅+震动跟 App 开不开无关
  • 本地通知(不是推送)：不需要服务器，提醒时间存在系统里，到点系统自己弹。即使 App 没运行、手表锁屏也会响。
  • 前台也能弹：默认 App 在前台时通知会被吞，我实现了 willPresent 代理强制显示——这就是你"Send test in 5s"能看到的原因。
  • "Send test in 5s"用的是 UNTimeIntervalNotificationTrigger(几秒后一次性)，专门用来验证权限通了没。

5.2 HealthKit（健康数据获取）

① 申请授权
第一次弹窗问你要不要给读心率/HRV。用户不同意就读不到。
② 被动读取
手表平时(睡眠/静息/呼吸)自动记 HRV 到 HealthKit，App 直接查历史。
③ 主动测量
Measure now 开运动会话拿逐拍，算真 SDNN。
HKObserverQuery注册"有新HRV叫醒我"
→
enableBackgroundDelivery后台投递
→
系统唤醒 App重算压力
→
刷新曲线+卡片不用你开 App

关键：App 不能强迫手表更频繁地采 HRV，采样频率由系统决定(平时较稀疏)。App 只能① 读系统已记录的；② 想要密集数据就开运动会话主动测。

免费开发者账号限制：HealthKit"后台投递"需要专门 entitlement，免费账号没有，所以 App 被系统回收后后台唤醒不保证；但只要你抬腕打开过一次 App，就会拉全当天所有真实样本。转正式账号($99/年)可彻底解决。

5.3 Widget / Smart Stack 卡片

Widget 是一个独立的扩展进程，和主 App 是两个程序，读不到对方的内存。所以靠 App Group 共享快照通信。

主 App 状态变
→
写快照到 App Group
→
WidgetCenter.reload通知系统
→
Widget 进程被唤醒TimelineProvider
→
读快照 → 画卡片

兜底：即使主 App 一直没开，Widget 每 30 分钟也自己刷新一次(Timeline policy)。卡片支持矩形/圆形/行内三种尺寸自动适配。

6和 iPhone App 的关系

现状：本 App 没有任何 iPhone 端。它是 WKWatchOnly: true 的纯手表独立应用——直接装进手表、独立运行、独立存数据。所以目前"iOS 数据存哪"这个问题：不存在 iOS 数据，所有数据都在手表上。

📱⌚️ 如果将来加 iPhone App

WatchConnectivity：两端互发消息/同步状态
各自独立沙盒：iPhone 和手表数据不自动共享，App Group 也不跨设备(只在同一设备内)
HealthKit 会自动同步：手表测的心率/HRV 会通过 iCloud 同步到 iPhone 的健康 App
iCloud / 服务器：要真正跨设备同步自己的业务数据，得用 CloudKit 或自建后端
三种"数据互通"的层次，别混淆
机制范围用途
UserDefaults单个 App 沙盒内自己存自己的设置/状态
App Group同一设备内，主 App ↔ 它的扩展(Widget)给卡片喂数据
WatchConnectivityiPhone ↔ 配对的手表手机端和表端实时同步(本 App 暂没用，因为没手机端)
HealthKit + iCloud同账号所有设备健康数据(心率/HRV)系统级自动同步
CloudKit / 后端跨设备、跨用户账号体系、云备份(本 App 暂没用)
