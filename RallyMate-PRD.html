1 产品定位与差异化

为什么再做一个羽毛球 app —— 因为现有玩家都没做的地方，正是用户最痛的地方。

一句话定位

"陪你打、护着你、让你坚持"的羽毛球手表应用：实时陪练（B）＋ 习惯陪伴（C）。

我们不卷"数得准不准、拍速多炫"（这是现有产品的红海，且口碑普遍塌房）。我们卷"过程中给你反馈、防你受伤、记录你的进步、督促你别三天打鱼"。

目标用户

🎯 主：羽毛球初学 / 进阶爱好者

每周打 1–3 次，关心"我运动量够不够、动作会不会受伤、有没有进步、能不能坚持"。不需要 0.1m/s 的拍速精度。

👥 次：想养成运动习惯的人

把打球当健康习惯，看重打卡、连续天数、成就感与温和督促（与陪伴路线契合）。

2 核心概念与术语

下游 UI / 文案 Agent 请统一使用以下术语，避免同义混用。

术语定义UI 展示用词
挥拍 Swing一次被传感器识别为有效击球意图的手腕动作（含空挥）。识别基于加速度峰值波形。挥拍 / 拍
强度 Intensity单次挥拍的相对力度，由加速度峰值归一化到 0–100（非真实球速）。用于区分轻挥与大力杀。力度 / 强度
回合 Rally一段密集连续挥拍（间隔 < 阈值）。回合之间是"间歇"。回合 / 多拍
间歇 Rest两个回合之间的休息时间（无挥拍）。间歇 / 休息
一场 Session一次从"开始打球"到"结束"的完整运动记录。这场 / 本场
运动负荷 Load本场累计强度（挥拍数 × 平均强度的综合量），反映身体消耗。运动量 / 负荷
疲劳信号 Fatigue挥拍强度相对本场基线持续下滑，判定为体力下降。累了 / 状态下滑
连续打球 Streak连续保持打球的天数 / 周数（陪伴激励）。连续打球 N 天
强度 ≠ 球速。UI 上严禁出现"km/h""m/s"这类绝对球速单位（这正是竞品被质疑虚高的雷区）。统一用 0–100 的"力度"或"轻/中/重"分级表达。

3 功能需求清单（N1–N13）

三层优先级：P0 MVP 立得住的基础盘 ｜ P1 差异化 别人都没有的核心 ｜ P2 未来 验证后再做。每条含验收标准（AC）。

P0 — MVP 基础盘

N1 挥拍计数 + 基础运动数据 P0

开一场"羽毛球"运动 session，实时统计：挥拍总数、运动时长、实时心率、消耗卡路里。心率/卡路里来自 HealthKit。

AC：真机佩戴打球，挥拍计数与实际明显挥拍次数误差 ≤ 15%；时长/心率/卡路里写入 Apple 健康；息屏后台持续计数不中断。

N2 挥拍强度曲线 P0

每次挥拍记录归一化强度(0–100)，全场聚合成一条随时间变化的强度曲线；区分轻挥 / 中等 / 大力(如杀球)三档。手机端为核心图表。

AC：详情页能看到整场强度曲线；大力挥拍在曲线上明显高于轻挥；曲线点可与回合对应。

N3 双手佩戴自适应 P0

不强制戴持拍手。支持"持拍手 / 非持拍手"两种佩戴模式，识别算法各自适配；首次启动引导用户选择，设置内可改。这是直接解决全行业硬伤的差异点。

AC：两种佩戴模式下计数都可用；切换模式后即时生效；UI 明确告知当前模式及对精度的影响。

N4 数据可靠 + 永不丢 P0

每场结束立即本地落盘；表→机同步具备重试与断点；后续支持 iCloud 备份。宁可朴素，绝不丢数据。

AC：杀进程 / 灭表后重开，已结束的场次仍在；同步失败有可见状态与手动重试；历史不会归零。

P1 — 差异化核心（陪练 B + 陪伴 C）

N5 疲劳预警（陪练）P1

实时追踪强度基线，当近 N 个回合的峰值强度相对基线持续下滑到阈值，判定"累了"，触发震动 + 表盘提示。全行业空白。

AC：主动制造体力下降场景能触发一次预警；不误报到每个轻挥；尊重"实时反馈开关"。详见 §7。

N6 回合节奏感知（陪练）P1

自动切分"回合 vs 间歇"，统计：回合数、平均每回合拍数、最长连拍、平均间歇时长、打/歇比。初学者常"回合短、歇太久"，这组数据很有用。

AC：一场能输出回合数与平均回合长度；最长连拍与详情曲线一致；间歇时长合理。

N7 过度使用 / 防伤提醒（陪练）P1

短时间内连续大力挥拍（如连续杀球）超阈值，提示"注意护腕/护肩，悠着点"。针对初学者最易受伤的场景。

AC：连续高强度挥拍达阈值触发一次防伤提醒；提示文案温和非恐吓；可在设置关闭。

N8 陪伴叙事 + 打卡（陪伴）P1

把数据讲成故事：里程碑("本周挥拍 1200 次")、连续打球天数、进步叙事("平均回合 4→7 拍，进步啦")。重点是情绪价值，不是冷数字。

AC：首页/详情出现至少 1 条人话叙事；连续打球天数正确累计与中断；里程碑达成有正向反馈。

N9 约球 / 打卡提醒（陪伴）P1

温和提醒用户去打球 / 记录约球时间。复用 MyWatch 已验证的通知 + 后台唤醒机制，工程成本低。

AC：可设置每周固定提醒；到点本地通知触达；提醒文案契合陪伴语气。

P2 — 未来（验证后再做）

N10 实时/赛后模式开关 P2

让用户自选"打球时震动陪练" vs "安静记录、赛后复盘"，解决"被打扰"的张力。建议 MVP 即提供基础开关，高级策略后置。

N11 对局记分 P2

竞品标配（单/双/混打计分），但非我们核心，后置。

N12 击球位置热力图 P2

手机摄像头标定球场 + 视觉追踪人 + 手表打点时间对齐 → 击球热力图 / 跑动轨迹。技术天花板高，最后做。

N13 徽章 / 成就系统 P2

借鉴挥拍吧的 3D 徽章增强陪伴粘性。可与 N8 合并演进。

5 Watch 端屏幕规格（W1–W8）

每屏含：目的 / 核心元素 / 数据动态 / 交互 / 边界状态。表盘尺寸按 45–49mm 设计，深色 OLED 优先。

W1今日首页

目的一眼看到今日运动量，一键开打。

核心元素顶部"今天"+ 大号挥拍数（今日累计）；中部一行小指标（连续打球 N 天 · 本周场次）；底部超大主按钮 「开始打球」（品牌渐变）。

数据动态今日无数据时大数字显示 0，副文案"今天还没挥拍，去打一场？"。

交互点主按钮→W2；上滑可见"最近一场"小卡（点→表端小结）；左滑→W8 设置。

边界无历史：隐藏"最近一场"，只留鼓励文案 + 开始按钮。

W2开始前准备

目的确认佩戴手 + 给身体一个起拍缓冲。

核心元素当前佩戴手标识（"持拍手 ✋" / "非持拍手"，可点切换）；实时反馈状态小标（"陪练模式 开/关"）；3-2-1 倒计时圈。

交互进入即开始倒计时；倒计时结束自动进 W3；可点中央"立即开始"跳过；返回回到 W1。

边界首次使用且未设佩戴手：先弹一次佩戴手选择再倒计时。

W3运动中 · 主表盘

目的打球时一瞥即得最关键数据。

核心元素正中超大挥拍数（本场累计，主视觉）；其下一行：时长 · 心率(♥ bpm)；底部一条实时强度条/火花线（最近若干拍的强度，随挥拍跳动，低=青绿、高=橙红的热度色）。

数据动态每识别一次挥拍，数字 +1 并轻微脉冲动画；心率随 HealthKit 刷新；息屏(Always-On)显示降采样的静态版。

交互左滑→W4 节奏；再左滑→W5 控制；表冠无操作。

边界心率未就绪显示"--"；长时间无挥拍底部条归零。

W4运动中 · 节奏页

目的感知当前回合与强度走势（陪练数据的实时面）。

核心元素当前/最近回合的拍数（"本回合 7 拍"）；间歇计时（回合结束后开始走"休息 0:12"）；最长连拍；一条小型强度走势 sparkline。

数据动态正在打 → 高亮"回合进行中"；停下 → 切到"间歇中"并计时。

交互右滑回 W3；左滑→W5。

W5运动中 · 控制页

目的暂停 / 继续 / 结束。

核心元素两枚大按钮：暂停/继续（琥珀色）、结束（珊瑚色）；其上小字本场已用时长。

交互点结束→二次确认（防误触）→进 W7；暂停时 W3 顶部显示"已暂停"。

边界结束确认为滑动或长按，避免打球误触。

W6实时反馈弹层（疲劳 / 防伤 / 里程碑）

目的陪练的"开口说话"时刻——关键节点震动 + 全屏卡片。

核心元素全屏色卡 + 图标 + 一句人话：疲劳=琥珀"你累了，注意动作别变形"；防伤=珊瑚"杀球有点多，护好手腕"；里程碑=薄荷"本场 500 拍达成！"。

数据动态触发逻辑见 §7；伴随对应触觉。2–3 秒后自动消失，回到运动中。

交互抬腕即看到；点一下可立即关闭；"实时反馈开关"为关时，本弹层不出现（事件改记入赛后报告）。

W7结束 · 即时小结

目的结束即给一份手表能看完的成就感小结。

核心元素顶部一句祝贺/陪伴文案；KPI 四宫格：挥拍数 · 时长 · 平均心率 · 卡路里；下方一行：最长连拍 · 平均回合；"详细分析请看手机"提示。

交互「完成」回 W1；上滑可见"本场亮点"（如新纪录）。

边界极短场次(<1 分钟或 0 拍)：提示"这场太短，未保存"，避免脏数据。

W8表端设置

核心元素佩戴手切换；实时反馈开关（总开关）；触觉强度（轻/中/强）；防伤提醒开关。

说明表端只放运动相关高频项；账户、单位、数据导出等放手机端 P7。

6 iPhone 端屏幕规格（P0–P7）

手机是"复盘 + 陪伴 + 设置"的主场，承载强度曲线、教练点评、趋势叙事。

P0引导 Onboarding

目的讲清价值 + 拿齐权限 + 设好佩戴手与模式。

分页① 价值主张（"会陪练、会护着你、让你坚持"）→ ② 健康权限(HealthKit 读心率/写运动) → ③ 通知权限(提醒) → ④ 选佩戴手(持拍/非持拍) → ⑤ 选模式(实时陪练 / 安静复盘)。

交互每页一句话 + 一张示意图 + 主按钮；权限页解释"为什么要"；可跳过非必需项。

边界拒绝健康权限：明确告知会缺心率/卡路里，并提供去系统设置开启的入口。

P1首页 · 仪表盘

目的进 app 第一眼：今日状态 + 坚持感 + 进步感。

核心元素顶部 Hero 卡：最近一场或今日概览（挥拍数大字 + 缩略强度曲线）；连续打球条（"🔥 连续打球 5 天"）；本周迷你柱状（每天挥拍量）；一条进步/陪伴叙事文案；底部"如何开始"引导（提示在手表上开始）。

交互点 Hero→P3 详情；点本周图→P4 趋势。

边界无任何数据：展示空状态插画 + "戴上 Apple Watch，在手表上开始第一场"。

P2历史列表

核心元素按时间倒序的场次卡：日期/时长 · 挥拍数 · 缩略强度曲线 · 是否有新纪录标记。可按周分组。

交互点任一场→P3；左滑删除（二次确认）。

边界空列表：引导开始第一场。

P3单场详情（核心报告页）

目的一场球的完整复盘 + 教练点评，是产品最重的页面。

核心元素 ① 概览 KPI：挥拍数 / 时长 / 平均·最高心率 / 卡路里 / 运动负荷； ② 强度曲线（N2 主图）：横轴时间，纵轴强度，热度配色，可缩放，叠加回合分段底纹； ③ 回合节奏（N6）：回合数 · 平均每回合拍数 · 最长连拍 · 打/歇比，配可视化； ④ 心率曲线； ⑤ 教练点评（B 的灵魂）：1–3 条人话洞察，如"后半场强度下滑明显，体能是短板""杀球占比偏高，注意手腕负荷""平均回合只有 4 拍，多打相持试试"； ⑥ 安静模式下，把当场未实时弹出的疲劳/防伤事件在此回放。

交互分享成绩卡；与上一场对比的小标签。

P4趋势

核心元素周/月切换；累计挥拍 · 打球天数 · 总时长；进步指标曲线：平均回合长度、平均强度、运动负荷随时间变化；进步叙事（"本月平均回合 4.2→6.8 拍，相持能力在涨"）。

交互点某周→该周场次列表。

P5成就 · 陪伴

核心元素连续打球天数大卡 + 日历热力格；里程碑列表（累计挥拍 1k/1w/10w、最长连拍纪录、单场负荷纪录…，含已达成/进度中）；徽章墙（P2，先占位）。

交互达成里程碑可生成分享卡。

P6提醒 · 约球

核心元素每周固定打球提醒（选星期 + 时间）；下次约球时间登记；提醒文案走陪伴语气。

说明复用 MyWatch 通知 + 后台唤醒机制；到点本地通知。

P7设置

核心元素佩戴手；实时反馈模式与各类提醒开关（疲劳/防伤/里程碑分别可控）；触觉强度；单位与偏好；HealthKit 权限状态与跳转；数据导出(CSV)；iCloud 备份开关；关于。

7 实时反馈设计（陪练核心）

这是羽伴区别于所有竞品的灵魂。下游需把"何时震、震什么、说什么"做成可配置且不烦人。

第一原则：少而准 > 多而吵。实时反馈宁可漏报也别误报刷屏——打球时被频繁打扰是体验灾难（竞品不敢做的真正原因）。每类反馈一场内有最小触发间隔（冷却）。
反馈触发条件（建议初值，需真机调参）触觉视觉(W6)文案示例
疲劳预警
N5		近 3 个回合峰值强度均值 ≤ 本场前段基线的 75%，且本场已 > 10 分钟。冷却 ≥ 5 分钟。双下轻击(soft)琥珀卡"你累了，注意动作别变形，要不要歇一下？"
防伤提醒
N7		2 分钟内"大力档"挥拍 ≥ 阈值（如连续高强度杀球多次）。冷却 ≥ 5 分钟。三连较强(notify)珊瑚卡"杀球有点猛，护好手腕和肩膀～"
里程碑
N8		本场挥拍数跨整数关口(如 500)、或刷新"最长连拍"纪录。轻快上扬(success)薄荷卡"本场 500 拍达成！" / "新纪录：连续 21 拍！"
心率过高
可选		心率持续超用户上限区间。冷却 ≥ 5 分钟。双下轻击琥珀卡"心率有点高，注意调整呼吸节奏。"

模式与降级：

  • 实时陪练模式（默认开）：以上反馈即时震动 + W6 弹层。
  • 安静复盘模式：全程不震不弹；所有本应触发的事件被记录，在 P3 详情页"赛后回放"呈现（"第 23 分钟你开始疲劳"）。
  • 每类反馈可在 W8 / P7 单独关闭。
所有阈值均为占位初值，必须在真机佩戴实测中标定（用户已有 Apple Watch 真机可测）。UI Agent 无需关心算法，只需把这些反馈做成 §6/§5 中描述的卡片与开关。

8 关键用户流程

① 首次使用

下载 App→ P0 引导 + 权限→ 选佩戴手 / 模式→ 手表 W1→ 开始第一场

② 打一场球（核心闭环）

W1 开始打球→ W2 倒计时→ W3/W4 运动中→ W6 实时陪练(按需)→ W5 结束→ W7 即时小结→ P3 手机详情复盘

③ 坚持与回顾（陪伴）

强度热度色阶（用于强度条/曲线）

低→高

强度 0–100 映射：低(青绿) → 中(黄) → 高(橙红)。轻挥偏冷色，大力杀球偏暖红。

背景

表端纯黑 #000（OLED 省电/Always-On）
机端深墨绿 #0b1410

字体与组件

  • 数字：大号、圆体(SF Rounded)，挥拍数等核心数字是主视觉，要"敢大"。
  • 正文/文案：San Francisco / PingFang SC；陪伴文案用人话、口语、带温度，少用术语。
  • 卡片：圆角 16（机）/ 12（表），半透明描边 rgba(255,255,255,.10)。
  • 图表：线条圆滑、渐变填充；强度曲线用热度色阶；避免花哨网格。
  • 反馈卡(W6)：全屏单色卡 + 大图标 + 一句话，情绪鲜明。
  • 图标气质：羽毛球/球拍/羽球元素可点缀，但克制，别卡通过度。

11 技术约束与依赖

平台 / 框架

  • watchOS 10+ / iOS 16+；SwiftUI。
  • CoreMotion：加速度计 + 陀螺仪做挥拍识别。普通采样(~100Hz)即可数次数；CMBatchedSensorManager(800Hz) 仅 S8/Ultra+，作为高精度增强可选。
  • HealthKit：读心率、写 Workout/能量。
  • WidgetKit：今日挥拍/连续打球小组件（后续）。
  • 表↔机用 WatchConnectivity 同步；本地持久化优先。

硬件 / 边界

  • 需带陀螺仪的 Apple Watch（Series 4+）；强依赖真机测试（模拟器无真实传感器）。
  • 挥拍识别是规则算法起步（峰值检测），不做动作分类(正反手/杀球细分留到后续 ML)。
  • 佩戴手影响波形 → N3 需两套阈值。
  • 强度为相对值，不对外宣称绝对球速。
  • 耗电：高频采样费电，需控制采样率与时长（竞品耗电是抱怨点）。

12 范围外 / 未来

  • 动作细分识别（正手/反手/杀球/高远/吊球）——需采数据训 CoreML，后置。
  • 击球落点热力图 / 跑动轨迹——需手机摄像头 + 视觉，N12，最后做。
  • 对局记分、社交/排行榜/约球地图、3D 徽章——P2 之后。
  • Android / 华为 / Garmin——不在本期范围。
